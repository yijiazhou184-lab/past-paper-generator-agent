For parts using symbolic or numeric calculation checks.
MathCheckSpec: represent arithmetic using the supplied restricted AST. Only numeric bounded powers and x,y,t,q are supported. Provide an explicit real interval domain. A derivative check's expected expression must be the actual final derivative; a value/limit check must match the final answer. Supply independent checks for every quantitative part; omit checks only for purely qualitative proof with no supported arithmetic. bounded_optimum must list every stationary point, every non-differentiable point inside the interval and both endpoints. Set role on every specification: core when expected is the part's final answer or a result the part explicitly asks for; auxiliary for supporting steps, domain or bound certificates and alternative routes. Each calculation or applied_optimisation part needs at least one core check. Do not label a final answer auxiliary. A lhopital check represents ONE application: give the numerator as expression and denominator separately, at/direction and expected limit. Repeated use needs separate specs and valid hypotheses each time.

Additional specifications are described by checker_contract and the supplied schema. Use maximal_domain to assert the complete domain as a union of intervals (an empty list means the empty set), preserving restrictions of original expressions before cancellation. All subexpressions must have real values. Fractional pow uses the principal real-valued branch: a nonnegative base for positive exponents, a positive base for negative exponents; do not use it as a signed odd-root operator. Use signed_limit for positive_infinity or negative_infinity with an explicit approach interval and direction. Infinity is a result label, never an arithmetic AST number.
Use parameter_derivative for polynomial identities with one declared real parameter, its interval, a decision variable and its interval. differentiate_by names either declared symbol; order is 1 or 2.
Use parameter_optimum for a polynomial objective on a finite closed decision interval with one parameter. Provide branches that cover the entire declared parameter interval with no overlaps or gaps, including threshold points. Each branch supplies an optimiser point and its optimal value as ASTs in the parameter alone. The checker proves feasibility, convexity or concavity, first-order conditions and value identities over entire parameter intervals. Numeric sampling is insufficient. Set unique=true when the answer claims a unique optimiser; this additionally requires a strict convexity/concavity or strict boundary-slope certificate over the entire branch.
Parameterized objectives and derivative identities accept polynomial ASTs of total degree at most 8, integer powers 0..6 and rational coefficients as number leaves. Other expressions or objectives without a decidable curvature certificate require further capability; report unable_to_determine with the exact unsupported requirement. Do not describe checker limitations as missing course information. Do not omit or weaken a required claim to obtain a pass.

Use parameter_identity for polynomial equivalence (at:null) or a value at a numeric decision point (at:numeric literal). A point-value expected AST may contain the parameter alone.
