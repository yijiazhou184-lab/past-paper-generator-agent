# 生成输出上限与已验证大题复用

> 状态：**已实施**（2026-10-30，提交 27a8d5a），真实运行待授权。结果见[第四批记录](../../batch-4-validation.md)末节。

## 现状

- 所有模型调用共用一个输出上限 12,000：执行上下文里的 `max_output_tokens`，并且 `ModelCallSpec`（`le=12000`）和 `reserve_call`（`output_tokens <= 12000`）两处都写死了这个值。
- 近几次真实生成单题的输出：11,324、6,319、9,766、7,013（7496b3cb）；10,228、9,798、6,379、≥12,000 被截断（e94322bf）。4 道题里常有 1–2 道超过 9,700。
- 官方上限：[GPT-6.1 Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)写明最大输出 128K tokens（2026-10-30 查阅），所以 20k 在模型允许范围内。
- **复用机制已经存在，但用不上**：`generator.generate_group` 只在本任务和父任务中，按完全相同的 `input_hash` 查找已验证的大题，而这个 hash 包含整个 context hash。只要修改上限、时限等与生成内容无关的参数，hash 就会变，就无法复用。

## 方案

### 1. 只提高生成和修复的输出上限

- 执行上下文新增 `generation_output_tokens: 20000`，只用于 `question_pairs` 和 `repair` 两个阶段。盲解、语义核验、计数和可选核验仍为 12,000（可选核验仍为 4,000）。
- `ModelCallSpec` 和 `reserve_call` 的固定 12,000 改为全局上限 32,000（`MAX_OUTPUT_TOKENS`）；各阶段的实际上限由冻结的上下文决定，规划、页图转写等其他阶段的值不变。
- 预检中分别列出两种上限。

### 2. 相应的时限（需要你一并确认）

按实测速度（约 75–90 tokens/秒）估算，20k 输出约需 230–270 秒，超过现在 240 秒的单次时限。

- **生成和修复的单次时限：240 → 300 秒**（300 是现有的全局最高值）。其他阶段仍为 240 秒。
- **生成任务的总时限：600 → 900 秒**。7496b3cb 用了 575 秒（生成 226、检查 160、修复 95、最终检查 95）。如果单题生成到 20k，最坏情况约 850 秒，600 秒不够。

如果你不想放宽总时限，可以只改输出上限和单次时限，但遇到长题时，任务可能在核验或修复阶段因时限中止，已保存的阶段成果不会丢。

### 3. 重试时复用已验证的大题（仅第 0 轮生成）

- **查找范围**：同一课程、同一冻结快照（`input.snapshot_id` 相同）、已经结束的历次生成任务，从新到旧查找。
- **复用条件**（全部满足才复用，任一不同就重新生成）：
  - 模型、`question_pairs` 提示词、配对 schema 的 hash、检查器契约、来源政策、整个 `input` 都与当前上下文相同；
  - 该大题的生成输入（包括已生成的前面几题摘要）与当前相同。用对方任务自己的 context hash 重新计算 `input_hash` 来比对；
  - 已验证成果的 payload hash 校验通过，并且用**当前的** `validate_group` 重新校验一遍。
- 输出上限、时限、核验策略不参与比较：它们不影响已完成大题的内容是否有效。
- **记录**：复用的大题在新任务里保存为阶段成果，注明 `reused_from_task` 和原调用 ID；任务页和审计脚本都会显示哪些大题是复用的，不把复用说成本次新生成。复用不发起模型调用，不占调用额度。
- 修复（第 1 轮）不跨任务复用，因为它取决于本次的检查报告。
- 按这些条件，e94322bf 已验证的 Q1–Q3 可以在下一次运行中复用，只需重新生成 Q4。前提是 Q1、Q2 的摘要不变，这一点由 hash 保证。

### 4. 测试

- 生成阶段使用 20k 上限，其他阶段仍为 12k；超过全局上限会被拒绝。
- 复用：快照相同、生成依据相同时复用，并重新校验；提示词、schema、input 或前面几题摘要任一不同就不复用；复用不调用模型、不占额度，并记录来源。
- 用 e94322bf 做本地离线验证：只计算新上下文下 Q1–Q3 能否复用，不调用模型。
- 全量后端和前端测试。

## 影响与授权

上下文新增或修改了 `generation_output_tokens`、单次时限和总时限，context hash 会改变，需要新的出卷预检和授权。复用会让下一次真实运行只为 Q4 发起生成调用，后续的核验流程照常执行。如果核验输入超过 60k 触发拆分，按约定专门记录。
