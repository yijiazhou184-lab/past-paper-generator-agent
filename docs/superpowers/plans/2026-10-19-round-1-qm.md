## Global Constraints

- 英语界面、题卷和 mark scheme；项目说明中文。
- 不覆盖现有需求、技术文档、历史原型和接入准备文件；本阶段不安装依赖、不修改运行环境、不调用真实模型。
- 首轮为一个课程、Topic 2、数字 PDF、Chapter practice、Foundation / Exam-standard / Challenge、三类作答要求、大题数 2–4；这些是本轮待确认建议，不是全产品永久上限。
- 课程范围输入采用用户声明“全部 lecture”，保存为 `User-provided scope`；不冒称官方事实，不再要求补齐官方公告才能开工。
- 信息缺口进入 AI①的“发现 → 必要提问 → 保存回答及来源 → 更新草稿 → 确认”流程；只阻塞受影响目标，不因无关章节缺资料阻塞全部。
- 原材料不移动、不删除、不改写；同 hash 复用解析成果并保留所有路径映射；引用固定 material/parse version 与物理页。
- 配置变化使结构确认失效；所有任务输入不可变；取消和唯一发布由数据库裁定。
- 网页、题卷 PDF、答案 PDF 使用同一 frozen content；两个文件齐备才完成；PDF 重试不重新生成题目。
- 未检查、无法判断、失败和不适用分别记录；严重错误不得作为 warning 放行；六次验收保存所有失败与超时。
- 临时限额以设计第 3.5 节 `r1-limits-proposal-1` 为准：超过 120 秒继续但标目标超时；硬截止与调用预算必须执行。
- 真实 API 试运行前确认账户/地区、凭据注入、实际外发范围及数据保留；不读取或展示真实密钥，不默认记录全文。
- 六次首轮验收不能代表全部 P0 和完整 MVP 的 18 × 3 正式评测完成。

## Review Focus

1. 同字节 PDF 的多路径、同名不同内容、替换后旧页引用：保留路径与版本，旧引用不能跳新页。归属 Task 2。
2. 用户已回答考试范围但没有官方公告，或无关 lecture 局部“不考”：保留 user_statement 来源，按目标处理冲突，不阻塞 Topic 2。归属 Task 3。
3. 自动保存乱序、多标签修改、旧规划晚到和“改回原值”：不能覆盖新输入或隐式恢复结构确认。归属 Task 4、6。
4. worker 重复领取/重启、取消与发布竞争、迟到模型结果：至多一份发布，取消先提交后不复活。归属 Task 1、10、11。
5. 一份 PDF 失败后重导、答案预取、源公式故意错误：重试同内容、默认不泄露答案、未核验不宣称正确。归属 Task 8、9、10。

### 0.3 类型与接口共享规则

数据 payload 的具体字段以设计第 5、6 节为准。Python schema 放相应 `schemas.py`，对外 DRF serializer 与其共享验证函数；OpenAPI 导出 TS 类型。以下缩写不是另造 schema：

- `TaskRef = {task_id, state}`；`ExecutionToken = {task_id, epoch}`，在 `app/core/types.py`。
- `EvidencePack = {manifest_hash, material_versions, parse_versions, evidence, statement_ids}`，在 `app/materials/schemas.py`。
- `CourseDraftPayload / Claim / Clarification / UserStatement` 在 `app/courses/schemas.py`。
- `GenerationConfig / BlueprintPayload / GenerationSnapshot / QuestionPair / CheckReport` 在 `app/generation/schemas.py`。
- `PaperView / MarkSchemeView / ArtifactSet / PublicationResult` 在 `app/papers/schemas.py`。
- `StageResult[T] / Issue / ModelCallSpec / ModelCallResult` 在 `app/ai/contracts.py`；`ModelCallSpec` 包含 stage、schema、prompt/context、model config、budget reservation，`ModelCallResult` 区分 parsed/refusal/truncated/provider_error。
- `AuthContext` 包含 owner_id；`IdempotencyInput` 包含 owner、operation、key、request_hash。
- `SourceView` 在 materials schemas，包含 evidence/version IDs、物理页、印刷页码、bbox 和授权页图；`PrivateStorage` 在 materials storage，是服务端生成 key 的读写接口，调用者不能指定任意磁盘路径。
- `AssetSpec / AssetRef / MathCheckSpec / CheckResult / ReviewInput / DuplicateCandidateSet / GateDecision` 在 generation schemas。`MathCheckSpec` 包含 part_id、受限表达式 AST、变量/定义域、比较方式和精度；`ReviewInput` 包含候选、蓝图/课程、程序检查及实际比较集合；CheckResult 使用设计第 5.5 节检查状态。`AssetRef` 为资产 ID/hash/type；`DuplicateCandidateSet` 带候选与检索覆盖；GateDecision 为 allowed + blocking_check_ids。
- `TaskView` 在 core types，字段见 Task 10；`MaterialVersion / ParseVersion / CourseDraft / CourseVersion / StructureConfirmation / CandidateVersion / ContentVersion` 是相应应用的持久实体，只通过服务函数改变允许修改的状态。`BinaryIO / Path / UUID` 为标准库类型。

服务函数必须接收 AuthContext 或从已授权的 task snapshot 派生归属；禁止“内部函数不用鉴权”形成跨课程资源绕过。API error/版本冲突按设计统一。

## 8. 提交、依赖与交付安排

稳定提交顺序为基线 → T1 → T2 → T3/T4 → T5/T6 → T7/T8 → T9/T10 → T11 → T12。一个 task 可有小提交，但批次结束应是可单独启动检查的稳定点；失败现场保留诊断，不把未通过结果写“完成”。若变更影响共享 schema，先更新契约并生成类型，再推进调用方。

可独立推进的内容：

- 环境验证与前端布局/静态契约样例可分别进行，不需要等课程所有问题回答完。
- 材料去重、来源查看、草稿 CAS、确认 hash、任务幂等和错误记录可用离线样例开发。
- 模型提示词和 schema 可先做静态评审及契约测试；质量和两分钟结论必须等真实运行。
- 打印模板可用人工构造的长题/公式样本先验证，最后仍需检查六份真实输出。

需等待依赖的内容：

- 未批准环境准备时不安装 Docling 权重、浏览器或容器服务。
- 未满足真实数据外发条件时不调用模型；这不阻止其余工程。
- 未有有效课程/结构确认时不提交正式生成；用户回答带来的新快照不能套用旧确认。
- 未有双 PDF 和发布 gate 时不呈现完整成功。

实施后的交付报告应包含实际修改、真实运行命令、检查结果、限制、六次结果路径及未完成 P0；不得把本文复述成执行结果。
