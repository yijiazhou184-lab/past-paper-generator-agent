## 2. 背景、目标用户与场景

### 2.1 问题与产品定位

大学生备考时通常只有少量 past papers、mock papers 和日常课件。重复刷已有题目难以区分“记住答案”与“掌握知识”，较简单的课堂练习也无法充分检验正式考试所需的综合能力。

产品使用学生提供的课程材料建立课程范围、知识深度与考试特征，生成新的练习试卷及配套 mark scheme，帮助学生自行检验理解。产品不预测真实考试题，不将生成卷或答案标为官方材料，也不承诺提升成绩。

### 2.2 用户与角色

| 角色 | 主要诉求 | 首版权限或参与方式 |
|---|---|---|
| 备考学生 | 得到贴近本课程范围、深度和考试形式的额外练习 | 管理自己的课程与材料；确认课程；生成、查看和删除自己的练习 |
| 产品负责人／主要测试者 | 判断生成系统是否可靠并找到改进方向 | 固定测试任务、核对资料、组织离线评测及试用验收 |
| 另一个评估 AI | 辅助独立解答、核查与一致性评估 | 参与离线测试；不作为学生必须使用的第二个产品角色 |
| 任课老师／学过该课程的学生 | 提供专业反馈 | 零星定性访谈或样本反馈；不作为每卷交付的必经审批人 |

Accounting、Business Analytics（BA）、Quantitative Maths（QM）是首批验证课程，不是产品唯一允许创建的课程。对其他课程的能力不能仅凭三门样本推广；资料不支持的题型或任务应明确提示。

### 2.3 核心场景

| 场景 | 触发条件 | 用户期望 |
|---|---|---|
| 首次建立课程 | 准备开始复习，持有教学资料和明确考试范围 | 系统整理课程理解，用户能检查和纠正 |
| 完整模拟卷 | 希望按接近真实考试的结构进行练习 | 一份结构完整、内容范围明确的新卷及对应答案 |
| 章节练习 | 希望集中练习若干章节 | 控制范围、难度、题型及大题数 |
| 多次练习 | 已练习一套，希望继续验证掌握程度 | 新题避免实质重复，逐步拓展知识覆盖 |
| 课程材料更新 | 获取新课件、考试公告或评分说明 | 看见哪些判断变化，保留之前的人工修改和旧试卷 |
| 资料不足或处理失败 | 缺少范围、局部解析错误、服务异常 | 知道具体原因、影响和恢复方式，不丢失已有工作 |

## 3. 产品目标、成功指标与首版范围

### 3.1 目标及衡量方式

| 目标 | 指标 | 首版要求 |
|---|---|---|
| 真实完成练习交付 | 从合格材料到课程确认、出卷、网页与两个 PDF 的端到端成功情况 | 第 11 节的功能验收必须通过，不以原型测试替代 |
| 符合用户确认的课程和配置 | 范围、题型、题量、分值、题答对应检查 | 固定验收样本中确定性要求 100% 符合 |
| 内容有可核查的质量依据 | 独立解答、数值检查、来源核查、开放题评估 | 严重已确认内容错误修复并复测；其他阈值按基线冻结 |
| 提供更多有效练习 | 实质重复率、累计知识点覆盖 | 与上传题及本人本课程历史分别比较，不承诺固定套数全覆盖 |
| 等待时间可接受 | 分析及完整生成的达标比例、原始耗时和超时数 | 两项均以小于 120 秒为目标；口径见第 10 节 |
| 问题可发现、可恢复 | 异常正确处理、误阻断、漏阻断、重试恢复情况 | 必须有可操作恢复路径及诊断记录 |

保存试卷、再次生成和下载等行为可用于观察试用流程，但不能直接证明学习效果。首版不设未经验证的分数提升、留存或商业收入承诺。

### 3.2 首版范围

- 完整模拟卷和章节练习同等重要，均为 P0。
- 英语界面、英语题卷与英语 mark scheme。
- 支持 PDF、PPT/PPTX、Word（DOC/DOCX）及数字文档内的图像、图表、公式、表格。
- 支持按课程考试需要使用财务报表、统计/数学图形、公式表等必要素材。
- 支持纸笔和计算器可完成的考试任务；具体允许的辅助资料以确认的课程考试规则为准。
- 学生直接编辑并确认课程理解；每次生成一套，可再次生成整卷；输出后自行核对答案。
- 保留材料、课程设置和历史，支持删除；本地自测与受邀线上试用均包含在首版交付中。

### 3.3 优先级与非目标

第 5 节的 P0-01 至 P0-14 全部为首版必做，可分阶段实现，不能只完成其中一条演示链路就视为首版完成。

**首版排除**：上传学生作答或自动批改；扫描件及手写识别；批量出卷；单题替换；Excel/Python/R 作答环境或代码/数据集交付；公开题库；课程共享；支付订阅；教师管理后台；学习成绩预测。

**后续候选**：高级学习分析、个性化练习路径、题目收藏。上述候选尚未承诺排期，不作为首版验收项。

## 4. 用户旅程、页面与交互

### 4.1 主流程

**进入课程 → 上传资料 → 分析课程与考试特征 → 编辑并确认课程 → 设置本次练习 → 核对本次试卷结构 → 生成 → 分别查看题卷与答案 → 下载／查看历史／再次生成。**

首轮课程确认之后，用户可以直接配置下一份练习。课程材料或人工定义发生变化时，展示差异并重新确认受影响的内容。参数调整仅影响本次练习，除非用户返回课程设置明确修改默认值。

### 4.2 页面职责

| 页面 | 主要输入与展示 | 主要操作 | 状态与关键反馈 |
|---|---|---|---|
| 登录／My courses | 邀请访问、本人课程、课程状态 | 登录、退出、创建、选择、重命名、删除 | 未授权、空列表、课程需确认、运行中 |
| Materials | 文件、材料类型、试卷与答案关联、解析定位 | 上传、替换、纠正类型、关联、删除、提交分析 | 上传中、读取中、局部问题、缺少范围或教学资料 |
| Course profile | 知识树、深度、范围、考试模板、证据 | 直接编辑、查看来源、核对差异、确认 | 推断、冲突、证据不足、未确认、已确认版本 |
| Generate | 两种练习模式、章节、难度、题型、大题数、结构摘要 | 配置、查看变更、编辑并确认新结构、开始生成 | 参数冲突、偏离原模板、依据不足、任务进度 |
| Papers | 历史列表、题卷、mark scheme、配置与课程版本 | 预览、切换答案、分别下载、反馈问题、删除、再次生成 | 空历史、完成、导出失败待恢复、原来源已删除 |

### 4.3 交互原则

1. 摘要优先；不确定项、冲突和证据缺口显著展示；详细证据按需展开。
2. 课程范围和结构通过可编辑控件修改，不以对话指令作为唯一修改入口。
3. 无结构变更时，用户在生成页检查摘要并点击生成，即确认本次配置；有结构变更时必须先确认新结构及差异。
4. 题卷默认可见；mark scheme 需要用户主动打开，避免提前暴露答案。
5. 进度显示实际阶段与已用时间，不显示伪造百分比；已完成、失败和仍在处理必须区分。
6. 错误说明包含“发生什么、影响什么、下一步怎么做”；不只显示内部错误码。
7. Gold set 和独立解题属于离线开发评测，不增加学生逐卷申请人工审批的步骤。

## 5. 首版功能需求与逐项验收

本节各功能均包含需求编号、来源、用户目标、前置条件、输入输出、业务规则、异常与恢复和验收标准。AC 编号用于关联测试证据；跨模块规则见第 6 至 10 节。

### P0-01 受邀账户与独立课程空间

- **来源**：R 线上独立账户和课程空间；S 课程重命名及权限验收。
- **用户目标**：安全地管理自己的课程，在再次访问时恢复已有工作。
- **前置条件**：线上为有效受邀身份；本地使用受控测试身份，不提供公开无认证的在线入口。
- **输入输出**：登录信息、课程名称及操作 → 身份会话、课程列表、课程详情和操作结果。
- **业务规则**：支持登录、退出、恢复访问和创建/选择/重命名/删除课程。每份材料、任务、历史和下载均归属用户与课程；课程重命名不改写旧试卷快照。首版不支持共同编辑或跨用户共享。
- **异常与恢复**：未授权或过期会话要求重新登录；重新登录后能找回本人任务与历史。其他用户资源统一拒绝访问，不泄露其内容。删除规则见 P0-14。
- **验收标准**：
  - **AC-01-01**：受邀用户登录后可创建两个课程；切换课程时只呈现对应材料、配置和历史。
  - **AC-01-02**：退出后不能直接访问受保护资源；重新登录后数据仍在。
  - **AC-01-03**：用户 A 不能通过页面、资源标识或旧下载链接读取、修改、删除用户 B 的材料、任务或结果。

### P0-02 上传、材料分类与答案关联

- **来源**：R 文件格式、资料类型和官方答案；S 上传失败恢复与文件约束。
- **用户目标**：将课程资料集中到对应课程，纠正系统对材料类型及对应关系的理解。
- **前置条件**：有该课程访问权；文件在上线前冻结的容量和格式支持范围内。
- **输入输出**：PDF、PPT/PPTX、DOC/DOCX 文件 → 已保存原文件、材料记录、分类结果和试卷/答案关联。
- **业务规则**：支持多文件选择及拖放。分类可建议，但必须读取内容，不能仅凭文件名认定范围或题型。用户可修改材料类型、关联/解除官方答案与试卷；一份答案可覆盖同一课程的多份试卷，但须明确对应范围，不能自动套用于所有试卷。重名不等于同一文件；完全相同内容重复上传需提示而非重复计入证据。
- **异常与恢复**：格式不符、损坏、加密不可读、超限或上传失败，定位文件并允许重传、替换或移除；成功的其他文件保留。实际格式与扩展名不一致不得按扩展名冒充支持。后端及界面一致执行限制。
- **验收标准**：
  - **AC-02-01**：五种扩展名的有效数字文档均进入真实解析链路；混合上传中失败文件不清除成功文件。
  - **AC-02-02**：将课件命名为“past paper”不会仅凭名称成为考试范围或考试模板的证据；人工分类修正可保存。
  - **AC-02-03**：答案关联可修改，删除或替换试卷后相关关联提示失效，不悄悄关联到另一份试卷。
  - **AC-02-04**：重复、加密、损坏及超限样本均有明确反馈；重复点击不产生同一上传的多个有效记录。

### P0-03 数字内容解析与来源定位

- **来源**：R 支持数字文档内图像、公式、图表和表格；S 解析状态及定位规则。
- **用户目标**：系统能够理解出题所需的实际内容，并让用户核对依据。
- **前置条件**：文件上传成功且可访问。
- **输入输出**：原文件及类型 → 可用于理解的文本、结构、公式、表格和图像内容，附来源位置及未可靠解析的项目。
- **业务规则**：保留公式上下标、单位、表格行列关系、图例与坐标含义等对内容理解必要的信息。PDF 使用页码，PPT/PPTX 使用幻灯片编号；Word 使用保存时的稳定页呈现，无法稳定分页时使用章节/段落定位。扫描件与手写仍不在首版范围；数字文档内的教学图表不能因此被整体忽略。
- **异常与恢复**：局部失败标出文件、位置、受影响知识点及建议操作；关键证据不可读时暂停受影响任务，其他章节仍可按支持情况练习。不得把无法识别的公式默认为空或补造为已读内容。
- **验收标准**：
  - **AC-03-01**：含公式、表格、图表的真实样本能定位原始内容并保留关键语义；核查缺失和错读清单。
  - **AC-03-02**：选定证据可回到同一材料版本的页/幻灯片/段落；替换原文件不会使旧引用错误指向新页。
  - **AC-03-03**：扫描件、手写及人为损坏的关键公式样本明确报告不支持或不可靠，不呈现为成功理解。

### P0-04 课程知识、范围与证据覆盖

- **来源**：R 教学资料与明确范围必需；S 范围覆盖的可核查表达。
- **用户目标**：知道系统理解了哪些课程知识，以及哪些内容有足够依据出题。
- **前置条件**：已提交材料分析；至少有教学资料和明确当前考试范围，或可明确报告其缺失。
- **输入输出**：教学内容、范围文件、辅助练习和来源 → 章节/知识点、掌握要求、纳入/排除范围、知识依赖、覆盖及缺口。
- **业务规则**：将“属于考试范围”与“有足够教学证据出题”分别记录。课件出现某主题不等于一定考查。仅有试卷和答案不能替代教学资料；外部补充不能替代学生必须提供的明确考试范围。
- **异常与恢复**：缺范围、缺教学资料或关键主题证据不足时说明具体缺口。允许补充材料或调整目标范围；不强制为可完成的章节练习补齐整个课程的所有材料。
- **验收标准**：
  - **AC-04-01**：只有 past paper+答案，或只有课件但没有明确考试范围，均不能直接完成出卷。
  - **AC-04-02**：对人工核对的参考清单，范围内/外项目、知识要求和证据缺口可逐项比较并追踪来源。
  - **AC-04-03**：材料只充分支持部分章节时，可对支持的已确认章节练习；包含未支持内容的请求得到具体缺口提示。

### P0-05 考试特征与模板

- **来源**：R 优先参考历年卷、无历年卷可继续；S 模板证据与多版本处理。
- **用户目标**：得到接近本课程考试形式与深度的练习，而非通用知识问答。
- **前置条件**：有课程范围及教学资料；历年卷、mock paper、官方解答和 rubric 按可用情况提供。
- **输入输出**：课程资料及试卷样本 → 题型、分区、大题/小题结构、分值、时长、必答/选答、辅助资料规则、推理深度和综合程度。
- **业务规则**：当前明确考试说明决定结构约束；past paper 优先支持出题风格和复杂度。多份试卷的共同规律与差异分开呈现，不把一个年份的偶然题目当成永久规则。没有 past paper 或明确结构时，提出基于可用资料的建议模板，标记推断并交用户确认。
- **异常与恢复**：互相冲突或版本不明的材料显示证据，请用户澄清；不得以旧卷覆盖已明确更新的范围。无历年卷本身不作为失败条件。
- **验收标准**：
  - **AC-05-01**：能提取和编辑样本的分区、分值、题数、选答与时长，且引用支撑材料。
  - **AC-05-02**：缺历年卷时仍能提出建议模板，并在课程确认、生成设置和历史配置中保留“未校准”信息。
  - **AC-05-03**：当前范围排除但旧卷包含的主题不会自动加入目标范围；关键版本冲突得到提示。

### P0-06 直接编辑、课程确认与版本管理

- **来源**：R 先确认再生成、直接编辑、更新保留人工修改；S 差异与版本冻结。
- **用户目标**：纠正系统理解，并在后续练习中复用可靠的课程设置。
- **前置条件**：已形成可编辑的课程分析或更新草稿。
- **输入输出**：用户对范围、知识、深度和考试模板的编辑 → 草稿、变更摘要及已确认课程版本。
- **业务规则**：支持编辑章节名称/范围/要求/深度、题型、分区、题数、分值、时间和必答/选答。区分用户修改与原资料陈述。更新材料时保留修改，展示受影响项和冲突；新版本确认前不能用于生成。确认不是准确性证明，不得自动消除仍存在的关键证据缺口。
- **异常与恢复**：分值不一致、选答数无效、范围冲突或必需证据未解决时指向字段。离开页面后可恢复已保存草稿；旧确认版本与历史不被覆盖。运行中快照与新编辑分离，见第 8 节。
- **验收标准**：
  - **AC-06-01**：编辑、返回页面、刷新后可找回已保存输入，确认后生成页读取该版本。
  - **AC-06-02**：更新或删除材料后展示受影响项，保留人工编辑并要求重新确认；无声覆盖视为不通过。
  - **AC-06-03**：无效分值、选答规则及关键冲突不能通过确认；旧试卷保持旧版本的内容和配置。

### P0-07 练习配置与本次试卷结构确认

- **来源**：R 两种模式、自定义参数，以及“提出新结构供确认”的明确选择。
- **用户目标**：得到符合本次练习目的、且可提前理解结构的试卷。
- **前置条件**：课程版本已确认；选定范围具有出题依据。
- **输入输出**：模式、章节、整卷难度、题型、大题数 → 本次结构草稿、相对课程模板的差异、确认后的生成配置。
- **业务规则**：完整卷默认沿用模板；参数变化影响结构时，提出新的分区、题型分布、题数、分值、必答/选答、总分、建议时长和计划知识覆盖。用户可编辑并确认；修改参数后原结构确认失效。允许一个大题包含多种作答要求和多个知识点，不能仅按“章节数大于大题数”判定不可行。精确规则见第 6 节。
- **异常与恢复**：结构不一致、用户约束不可同时满足或资料不足时，说明原因并提供调整方向；不得忽略题型、偷偷扩大范围、固定总分/时间或改成全必答来消解冲突。
- **验收标准**：
  - **AC-07-01**：两种模式和三档难度均可配置，结果反映确认的范围、题型、大题数和结构。
  - **AC-07-02**：修改题量/题型导致结构变化时，先展示差异和新结构；未确认不能提交正式出卷。
  - **AC-07-03**：本次自定义不改写课程默认模板；原型的固定小题数、分值、时长和题数上限不成为产品规则。
  - **AC-07-04**：预估小题数量与最终实际数量区分展示；如用户已经锁定该数量，输出必须符合。

### P0-08 新题及配套 mark scheme 生成

- **来源**：R 核心出卷任务、各类答案要求及课程必要图表。
- **用户目标**：获得可以独立完成、能够自行核对的新增练习。
- **前置条件**：本次配置及结构已确认；输入版本被冻结。
- **输入输出**：课程与材料快照、本次配置、来源证据和历史参考 → 一套新题、完整 mark scheme 及必要图表/报表/公式表。
- **业务规则**：每次一套；以课程知识与考试认知要求组织新题。计算题含结果、过程、单位/精度及评分点；解释题含必要要点和理由；案例/论述题含完整示例答案、评分点和可接受替代观点。没有官方细分分值时标注建议性质。题目具备充分条件，合理开放性与无解/歧义错误必须区分。
- **异常与恢复**：内容不完整、模型失败、题答不一致或必要图表无法形成时保留配置并修复或重试；不能以半份题卷当成功。不能通过增加范围外知识满足 Challenge。
- **验收标准**：
  - **AC-08-01**：题卷覆盖本次确认的结构，所有实际题目均有对应答案及可用于自查的解释。
  - **AC-08-02**：分别核验计算、解释、案例/论述样本；不得用通用模板段落代替真实解答或完整示例答案。
  - **AC-08-03**：需要图表/财务报表/公式表的课程样本在题卷与答案中保留必要信息，支持纸笔或计算器完成。

### P0-09 一致性与实质重复检查

- **来源**：R 不超纲、题答和分值一致、避免实质重复；S 检查失败的恢复行为。
- **用户目标**：避免练习到结构错误、答案错配或只替换数字的旧题。
- **前置条件**：已形成候选题卷及 mark scheme。
- **输入输出**：候选内容、确认范围/结构、上传题及本人本课程历史 → 检查结果、修正后的候选内容或明确失败原因。
- **业务规则**：检查范围、题型、题数、题号、分值汇总、选答、解答对应和适用的计算约束。按数值和解法语义比较实质重复，不能仅比较字符串。检查是出卷流程内部能力；完整 Gold set 评测及独立评估 AI 不成为每份学生卷的审批步骤。
- **异常与恢复**：可修正问题在任务预算内自动修正并再次检查；无法解决时明确失败，保留配置。重试次数和运行上限上线前冻结，不能无限尝试。未能验证某项不等于已验证正确。
- **验收标准**：
  - **AC-09-01**：人为植入错题号、错总分、缺答案、范围外要求等样本时，能识别且不将未修正结果标记为成功。
  - **AC-09-02**：相同结构和解题路径仅换数值/名称的对照题能被标为实质重复；相同知识点但不同问题不被一律拒绝。
  - **AC-09-03**：量化计算验证报告同时记录可验证覆盖和检查结果，不把“没有执行检查”记为通过。

### P0-10 网页预览与独立 PDF

- **来源**：R 网页加两个独立 PDF、答案分开展示；S 同版本和完整交付。
- **用户目标**：能够先练习，再核对或打印。
- **前置条件**：内容形成并通过必要一致性检查。
- **输入输出**：同一份题卷与答案内容版本 → Question paper 网页、Mark scheme 网页、两个可下载 PDF。
- **业务规则**：默认打开题卷；答案由用户主动切换。题卷不夹带答案。所有输出使用同一内容版本，显示实际大题/小题数量。题号、分值、表格、公式和图形在网页及 PDF 一致；输出规范见第 7 节。下载需要权限校验。
- **异常与恢复**：某个 PDF 失败则任务未完整完成，保留已生成内容并允许重新导出；重导出不生成新题、不改写答案、不新增一份练习历史。
- **验收标准**：
  - **AC-10-01**：两个实际 PDF 均能下载、打开和打印，内容与对应网页一致；仅显示下载按钮不算完成。
  - **AC-10-02**：对长题、跨页表格、公式、图形及选答说明进行视觉核验，无截断、漏项、错位或答案泄漏。
  - **AC-10-03**：模拟一个 PDF 失败后重试，恢复的是同一份题卷内容；两个 PDF 与完整预览均就绪才显示成功。

### P0-11 历史记录与再次练习

- **来源**：R 持久保存、重新打开和下载、多次生成；S 快照与来源删除标识。
- **用户目标**：复用已生成的练习，并在同一课程继续练习。
- **前置条件**：存在本人课程及可查看的任务/完成记录。
- **输入输出**：历史选择或再次生成操作 → 原试卷快照、配置详情、下载结果或新的生成任务。
- **业务规则**：历史包含模式、难度、范围、题型、结构、生成时间、课程版本和未校准标识。历史详情使用当时快照。再次生成建立新任务，默认复用练习配置并以当前可用的确认课程版本核对；版本或范围变化需提示，不能直接复用失效配置。失败/取消记录与已完成试卷区分。
- **异常与恢复**：源材料被删除时，旧卷仍可查看，引用显示“原材料已删除”；旧 PDF 暂不可用时从已保存内容恢复导出，不能重新出题代替原卷。
- **验收标准**：
  - **AC-11-01**：刷新、退出再登录后可打开和下载历史；浏览器本地缓存不是线上持久化的唯一来源。
  - **AC-11-02**：课程名称、材料或范围更新后，旧卷及其配置不变；删除来源能看到正确失效标识。
  - **AC-11-03**：再次生成得到独立记录并纳入历史去重参照；配置在新课程版本下失效时先处理差异。

### P0-12 任务进度、取消及恢复

- **来源**：R 进度、超时继续、取消和重试；S 后台任务、幂等提交与课程并发限制。
- **用户目标**：知道任务是否在运行，并在失败或离开页面后恢复工作。
- **前置条件**：有效分析/生成提交，或存在可恢复任务。
- **输入输出**：提交、刷新、取消、恢复或重试 → 稳定任务标识、实际阶段、累计系统耗时及状态。
- **业务规则**：任务状态见第 8 节；同一课程只允许一个分析或生成任务处于等待/处理中。重复点击返回同一任务；主动再次生成属于新任务。刷新、关闭页面或重新登录不自行取消后台任务。超过两分钟标记超时但继续运行，用户可取消。
- **异常与恢复**：网络断开后以服务端状态恢复，不自动重复提交；可重试失败阶段保留输入及已完成成果。用户取消后不发布新结果。任务已完成与取消同时到达时，按服务端已经确认的状态反馈，不能让一个任务同时显示成功和取消。
- **验收标准**：
  - **AC-12-01**：重复提交、双标签页、刷新或重连不产生重复试卷；同课程忙碌时可跳转已有任务。
  - **AC-12-02**：超时样本显示仍在处理、已超过目标和取消入口；失败与超时分别记录。
  - **AC-12-03**：取消先被系统接受后，延迟返回的模型/PDF 结果不新增历史；已成功的结果不被误报为取消。
  - **AC-12-04**：重试生成失败保留配置；重试导出使用原内容；重新登录能恢复任务状态。

### P0-13 外部补充与来源说明

- **来源**：R 可以补充检索、说明来源和情况、仍不足则暂停。
- **用户目标**：在课程允许范围内补足确实缺少的知识说明，知道新增依据来自哪里。
- **前置条件**：已有教学材料和明确范围，分析发现可具体描述的证据缺口。
- **输入输出**：缺口、确认范围及课程上下文 → 有出处的补充内容、用途和支持程度，或未能补足的缺口。
- **业务规则**：系统可主动检索，但必须说明缺什么、为何检索、使用何来源及补充何内容。保存标题、网址、获取时间和相关片段。优先采用与课程匹配的可核查来源；外部信息不能覆盖明确课程规则或扩大范围。检索请求尽量使用必要概念，不发送整份私人课程材料或身份信息。
- **异常与恢复**：检索失败、网页无法访问、来源冲突或不能证明课程要求时，不编造结果。可依现有充足证据继续；目标仍缺依据则请求补充或调整范围。
- **验收标准**：
  - **AC-13-01**：每项采用的外部补充均有来源、原因、用途和相关证据，可与课程原始内容区分。
  - **AC-13-02**：无法取得外部证据时如实显示失败或不足，不显示虚构网址或“已核实”的结论。
  - **AC-13-03**：外部材料包含范围外方法或与课程约定冲突时，不自动用于新题；缺口未解决的目标暂停。

### P0-14 数据删除、诊断、反馈与评测记录

- **来源**：R 用户删除前保留数据；S 删除联动、最小反馈与运行记录。
- **用户目标**：管理自己的资料，并让出错任务或题目能被定位和改进。
- **前置条件**：有相应资源访问权；反馈关联本人任务或题目。
- **输入输出**：删除对象或问题反馈 → 删除状态、受影响范围、反馈记录；系统运行 → 脱敏诊断及评测关联信息。
- **业务规则**：文件、试卷和课程分别按第 9 节删除。破坏性删除先显示影响并由用户确认。提供最小反馈入口，包含问题类型、可选说明、任务/题目标识；不要求建设教师后台。记录处理版本、状态、阶段耗时、模型用量及可取得的成本估算；未取得的用量/价格不得记为零。
- **异常与恢复**：删除未完成时显示处理中或失败并可重试，不假称清除；反馈提交失败可重试且保留文字。任务诊断不默认收集完整材料、密钥或不必要身份信息。
- **验收标准**：
  - **AC-14-01**：分别验证删除材料、试卷和课程的级联结果、引用失效、任务取消和权限撤销。
  - **AC-14-02**：反馈能定位具体题目与生成版本，且不改变该试卷；相同反馈重试不产生无意义重复记录。
  - **AC-14-03**：失败、取消和超时任务有诊断标识与阶段记录；日志无密钥，原始课程全文不被默认写入。
  - **AC-14-04**：每份离线评测输出可以关联任务、材料/课程/模型配置版本及评估记录，复测可追踪。

## 6. 数据来源、课程理解与出卷规则

### 6.1 数据来源及其作用

| 来源 | 用途 | 必需性与限制 |
|---|---|---|
| 当前 syllabus 或其他明确考试范围说明 | 定义纳入、排除内容及明确考试要求 | 必需；不能仅从课件出现频率推测考试范围 |
| Lecture slides、seminar slides、handouts 等 | 课程概念、方法、术语、知识深度和例题 | 必需；需要支撑本次出卷目标 |
| Past paper / mock paper | 题型、结构、综合程度、计算量和命题风格 | 可选，有则优先参考；不能覆盖新的明确范围 |
| 对应官方答案 / mark scheme | 解法、表述、评分点和允许的答案 | 有则纳入；未提供分步分值时不得声称已有官方分值依据 |
| Rubric / marking guidance | 评分标准和质量要求 | 可选；缺失时生成建议评分并标明性质 |
| 小练习及答案 | 补充知识覆盖、基础方法与正确性参照 | 可选；不得直接假定其难度等同正式考试 |
| 外部补充资料 | 弥补已确认范围内的具体知识缺口 | 可选补充；必须记录用途、出处和支持情况 |

### 6.2 来源与范围规则

| 编号 | 规则 |
|---|---|
| BR-01 | 使用当前明确考试范围决定考什么；不以旧卷或外部知识扩大范围。年份新旧无法判断，或两个当前声明冲突时，先澄清。 |
| BR-02 | 使用课程教学资料确定本课程采用的方法、符号、术语、精度和深度；通用方法不能自动替代课程约定。 |
| BR-03 | 区分“原资料明确陈述”“从试卷归纳”“外部补充”“用户修改”；原始来源不能因人工编辑而被改写。 |
| BR-04 | 材料不足按目标影响处理。可完成的章节练习不依赖无关章节齐全；完整卷必须具有支撑其确认范围和结构的资料。 |
| BR-05 | 已确认版本允许保留其他章节的缺口记录，但不能据此为缺乏依据的目标出题。用户勾选确认不能使不可靠信息自动变成事实。 |
| BR-06 | 不相关页面的解析问题可保留提示后继续；影响题目必要条件、课程方法或正确答案的解析问题必须先解决。 |

### 6.3 课程分析与生成的处理顺序

1. **资料处理**：保留原文件及版本，解析结构和内容，形成可定位证据，并记录不支持或不可靠的部分。
2. **课程理解**：结合明确考试范围，整理知识树、要求、深度、依赖、纳入/排除项和证据缺口。
3. **考试理解**：归纳题型、题目组织方式、分区、评分、时长、选答及复杂度，区分共同规律和样本差异。
4. **用户确认**：展示草稿与证据，允许直接编辑；记录修正和版本，解决影响生成的关键问题。
5. **出卷组织**：将本次章节、题型、难度、题量映射到结构与计划知识覆盖，必要时提出新结构供确认。
6. **生成题答**：按确认快照形成新题、必要素材、解答和评分说明；每个作答单元能关联相应知识要求。
7. **内部一致性处理**：检查结构、题答、分值和适用计算，比较实质重复；在受控重试范围内修正问题。
8. **交付**：生成同版本网页和两个 PDF，持久保存完成结果及来源/配置快照。

以上是产品能力和数据流要求，不限定由单个或多个模型、固定工作流或其他技术方式实现。

### 6.4 练习配置和新结构确认

| 编号 | 规则 |
|---|---|
| BR-07 | 完整模拟卷默认沿用确认模板；章节练习聚焦选定章节。两种模式均支持章节、整卷难度、题型及大题数。 |
| BR-08 | 题型选项来自已确认的课程模板；用户不能在生成页临时引入未经课程确认的题型。需要新增题型时返回课程设置核对依据。 |
| BR-09 | 大题数量是顶层题目数，小题数量独立统计。一个大题可以包含多个小题、多种作答要求或多个知识点；题型统计应说明作用于大题还是作答单元，避免混用。 |
| BR-10 | 参数变动影响原结构时，系统必须提出新的分区、题型分布、题数、每题/每区分值、必答/选答、总分和建议时长，并展示相对原模板的差异。 |
| BR-11 | 学生编辑并确认新结构后生成；后续修改相关参数使该确认失效。不得自动改成全必答、固定总分或任意改变时长而不说明。 |
| BR-12 | 章节选择界定允许出题范围，不承诺单卷覆盖全部选定知识点。展示计划覆盖和未覆盖内容；明显无法实现的覆盖诉求先调整，不能默默忽略。 |
| BR-13 | 本次结构和配置不自动写回课程默认设置。历史再生成遇到课程版本变化时，先核对失效章节、题型与结构。 |
| BR-14 | 不允许“预计总分”与确认后最终总分不一致。建议时长可以是估计，但必须标明依据及是否偏离原考试；不能把原型的固定估时用作正式能力。 |

**结构一致性示例**：一个分区共 3 道题、每题 20 分，要求选答 2 道，该区应答总分为 40 分，而卷面列出的题目分值合计为 60 分。二者应分别明确；整卷总分按实际选答规则计算。若选答题分值不同，应能保证允许作答路径的应答总分一致，否则提示修改规则。大题与小题分值、分区与整卷分值应分别相符。

章节练习的总分和时间依据实际结构、内容复杂度及可用考试参照提出，由学生在开始生成前确认。没有充分历年卷依据时不得标注为已匹配正式考试。

### 6.5 难度定义

| 难度 | 命题侧要求 | 限制 |
|---|---|---|
| Foundation | 以单一概念、明确条件和直接应用为主，降低综合推理负担 | 仍需符合课程方法与范围 |
| Exam-standard | 参考正式试卷的推理步骤、跨知识组合、计算量及解释要求 | 无 past paper 时标注为估计，不能声称已校准 |
| Challenge | 在课程范围内增加知识整合、条件判断、推理或评价要求 | 不能依靠超纲知识、故意缺少条件或歧义增加难度 |

难度作用于整份练习，不等于每道题必须相同难度，也不能只用数字变大、题干变长来代表难度提升。量化评估方法见第 11 节。

### 6.6 实质重复与覆盖

- 实质重复指条件组织、题目结构与解题路径基本相同，只更换数值、人物或表面措辞；仅文本不同不足以证明新颖性。
- 相同知识点或通用公式再次出现不自动算重复；应结合问题要求、上下文及推理路径判断。
- 比较范围包括上传的正式卷、mock paper、小练习及本人本课程未删除的历史练习，不混用其他用户的私人内容。
- 单卷优先满足确认的考试结构和练习目标；多次生成记录累计知识覆盖，不承诺固定 N 套卷覆盖全部课程。
- 重复判定的相似度策略和质量阈值经基线验证后冻结；不能使用未校准的任意相似度数值作为已确认产品标准。

## 7. 题卷与 mark scheme 输出规范

### 7.1 题卷

| 内容 | 必须要求 |
|---|---|
| 身份与说明 | 课程名称、练习名称、生成练习标识；明确属于练习材料，不暗示为官方试卷 |
| 考试信息 | 确认的总分、时间、分区、必答/选答说明，以及本课程允许的辅助资料 |
| 题目结构 | 连续且唯一的题号、小题标识及分值；实际大题与小题数量可核对 |
| 条件与数据 | 信息充分，单位、舍入要求、假设、数据表及题内引用一致；不得依赖用户看不到的资料 |
| 视觉材料 | 必要图表、坐标、图例、公式、财务报表或公式表可读且完整 |
| 答案隔离 | 不含 mark scheme、结果、解题提示或会直接泄露解法的来源说明 |

### 7.2 Mark scheme

| 题目类型 | 必须要求 |
|---|---|
| 计算题 | 最终结果、关键步骤、必要推导、单位/精度/容差、评分点和适用的其他方法 |
| 解释题 | 必要概念、解释理由、可接受表达及评分点，避免只有关键词而无法自查 |
| 案例／论述题 | 完整示例答案、论证和证据要求、评分点、建议分值及合理的其他观点 |
| 所有题型 | 与题卷编号、条件和分值对应；区分官方评分依据与生成的建议分配 |

分步得分可提供建议部分分；没有官方细则时不得将其包装为官方规则。合理的等价解法、不同论证或措辞不能仅因不同于示例答案而被排除。评分点合计必须满足对应题目分值。

### 7.3 网页与 PDF 的共同要求

- 题卷与答案分别预览，分别生成 PDF；两份文件均绑定相同的练习内容版本。
- 分页不丢失题干、表格行列、分值、坐标轴或公式上下标。需要跨页时保留足够的题号/表头信息，使学生能够继续阅读。
- 字体、数学表达和图形在目标浏览器及 PDF 阅读器中可读；打印不截断必要内容。
- 来源说明在课程分析、试卷详情或答案证据区提供；已删除来源显示失效状态，不伪造仍可打开的引用。
- 未通过导出或仍有文件待准备时显示任务未完成。已经就绪的内容可标明为暂可预览，但不能等同完整交付。
- PDF 下载失败可重新请求；需要重建文件时使用保存的同一内容，不重复调用出题来替换原题。

## 8. 数据对象、版本与任务状态

### 8.1 最小业务对象

下表定义必须保留的业务信息，不是数据库设计或接口协议。开发设计需提供这些信息的对应实现与访问约束。

| 对象 | 最低必要信息 | 关系和生命周期 |
|---|---|---|
| 用户／访问身份 | 身份标识、受邀访问状态 | 拥有课程；线上所有资源操作校验归属 |
| 课程 | 所有者、名称、当前状态、当前确认版本 | 包含材料、草稿、确认版本、任务与历史 |
| 材料版本 | 文件标识、课程、类型、名称、实际格式、内容版本、上传/解析状态、关联关系 | 替换文件产生新版本；不能覆盖旧引用指向 |
| 证据条目 | 材料版本或外部来源、位置、相关片段、支持的知识/规则、解析可靠性状态 | 连接课程结论和来源；删除后不保留可检索全文副本 |
| 课程草稿／确认版本 | 知识树、范围、深度、考试模板、证据、人工修改、缺口和确认时间 | 确认生成不可变版本；新编辑保留在草稿 |
| 本次练习配置／结构 | 模式、章节、难度、题型、大题数、计划覆盖、分区/分值/选答/时长、确认状态 | 绑定课程版本；结构相关修改使原确认失效 |
| 任务 | 用户/课程、任务类别、状态、阶段、输入快照、重试关联、取消状态、时间和错误类别 | 服务端可恢复；不能由前端显示状态替代 |
| 题卷与答案内容 | 题号、小题、条件、素材、解答、评分点、来源、内容版本 | 同版本成对保存，供网页和 PDF 使用 |
| 输出文件／历史记录 | 对应内容版本、两个 PDF 的就绪状态、当次课程/配置快照、日期、未校准说明 | 完成结果持久保存；删除按第 9 节执行 |
| 问题反馈 | 反馈标识、本人任务/题目标识、类型、可选说明、处理状态 | 定位问题；不改写原卷，不默认向他人开放原始材料 |
| 评测记录 | 固定任务、生成版本、评估者、指标分子分母、证据、结论与复测关联 | 与离线评测关联；个人材料删除后按删除规则处理内容 |

### 8.2 版本与并发约束

1. 确认课程版本不可原地修改。每次分析或生成固定材料、课程和配置快照；模型与处理流程版本也用于诊断记录。
2. 同一课程最多一个分析/生成任务处于等待或处理中。另一标签页提交时返回已有任务，或明确要求先完成/取消；不创建不可见的竞争任务。
3. 运行期间的新增材料或课程编辑进入新草稿，不改变运行中的快照；后续出卷需使用适用的确认版本。删除运行中依赖的材料时，提示影响并先取消受影响任务。
4. “需要补充信息”的任务不无限占用执行资源。补充材料或修改配置后使用新快照恢复，并关联原任务；不能假称旧快照仍是当前输入。
5. 完成记录绑定当时名称、结构与内容。课程重命名、材料更新、配置调整不得导致历史题卷或答案悄悄变化。
6. 一个成功任务对应一个完成结果；导出重试恢复该结果，再次生成才创建新的练习。

### 8.3 状态定义与转移

| 状态 | 进入条件 | 用户看到的内容与允许操作 | 后续 |
|---|---|---|---|
| 等待 | 有效任务已被受理但尚未处理 | 已提交、真实排队状态、可取消 | 处理中／取消／失败 |
| 处理中 | 正在解析、分析、生成、校验或导出 | 当前阶段、已用时间、取消入口 | 需要补充信息／成功／失败／取消 |
| 需要补充信息 | 目标范围的关键输入不足或冲突不能解决 | 具体缺口、证据与调整路径 | 新快照恢复、关联新尝试；或取消 |
| 成功 | 分析的可编辑结果已就绪；或生成的完整预览和两个 PDF 都就绪 | 可编辑分析或完整练习结果 | 该次任务终态；后续为新操作 |
| 失败 | 服务、文件、生成、校验或导出无法在已设运行预算内完成 | 失败阶段、可理解原因、保留的输入与可重试动作 | 关联重试；原尝试记录保留 |
| 取消 | 系统接受用户取消，或资源删除导致取消 | 已取消、配置保留或资源已删除 | 原任务不再发布新结果 |

**“超过两分钟”是附加标记，不是终态。** 任务仍可完成，但在性能记录中已不达标；允许用户取消。两分钟不等于无限运行许可，最大运行时间和重试预算需在上线前冻结，见 V-07。

分析成功表示分析结果可供审阅，不等于课程已经确认，也不等于所有章节均有足够出题依据；这三个状态必须分别展示。

### 8.4 取消、失败与重试的边界

- 网络断连、页面关闭和用户主动取消不是同一事件；前两者不自动中止已受理的后台任务。
- 取消接受后，不能因晚到结果重新显示成功或新增历史。已提交外部服务的计算能否立即停止由技术能力决定，但必须阻止结果继续发布并记录实际用量。
- 若任务成功先于取消请求生效，反馈已完成，不能将同一结果同时标为取消；用户仍可删除结果。
- 自动重试耗时计入当前用户请求；人工重试保留原失败尝试及关联关系，不覆盖失败日志来改善统计。
- 内容已生成而 PDF 失败时只恢复导出。需要重新出题的恢复操作必须明确说明它会产生新内容。

## 9. 异常、恢复与删除规则

### 9.1 异常处理矩阵

| 编号 | 情况 | 阻止什么 | 用户反馈与恢复路径 | 对应需求 |
|---|---|---|---|---|
| EX-01 | 缺明确考试范围或必要教学资料 | 受影响课程的出卷 | 列出缺失资料，补充后重新分析；不从课件独立猜测考试范围 | P0-02、P0-04 |
| EX-02 | 无 past paper | 不因这一项单独阻止 | 标注结构与难度未校准，用户确认建议模板后继续 | P0-05 |
| EX-03 | 当前范围与旧试卷不一致 | 不采用旧卷的范围外要求 | 展示来源并以当前范围为准；不无故要求推翻明确的新范围 | P0-05、P0-06 |
| EX-04 | 两个当前范围声明冲突或版本不明 | 受影响范围的确认/生成 | 展示双方位置与内容，请用户提供澄清或有效范围说明 | P0-04、P0-06 |
| EX-05 | 文件格式、损坏、加密、超限或上传失败 | 该文件进入可靠分析 | 文件级原因、重传/替换/移除；其他成功材料保留 | P0-02 |
| EX-06 | 扫描/手写或局部公式、图表无法理解 | 依赖该关键内容的目标 | 指明文件位置和影响；补充或更换；与目标无关时不误阻断 | P0-03 |
| EX-07 | 目标章节证据不足 | 涉及缺口的生成 | 说明外部补充情况；仍不足则补充教学资料或调整范围 | P0-04、P0-13 |
| EX-08 | 题型、题量、分值或选答约束冲突 | 本次生成提交 | 指向冲突字段，提出新结构/调整方向，重新确认 | P0-07 |
| EX-09 | 内部检查发现错配、超纲或实质重复 | 未修正内容标记成功 | 有限自动修正；仍不能解决时失败并保留配置 | P0-09 |
| EX-10 | 超过两分钟 | 不立即中止处理 | 标记超过目标、仍在处理；可等待或取消；记录不达标 | P0-12 |
| EX-11 | 模型/服务失败或运行预算耗尽 | 本次完整交付 | 标明失败阶段，保留材料与配置，允许关联重试 | P0-08、P0-12 |
| EX-12 | 仅一个或两个 PDF 导出失败 | 完整成功状态 | 保留原内容，按同一版本重试导出 | P0-10 |
| EX-13 | 重复提交、刷新、断网或会话过期 | 不应新建重复任务 | 恢复已有状态；过期先登录；已受理任务继续运行 | P0-01、P0-12 |
| EX-14 | 用户取消或删除课程 | 任务继续发布新结果 | 明确取消/删除状态，阻止晚到结果复活 | P0-12、P0-14 |
| EX-15 | 删除清理或反馈提交失败 | 不能假称操作完成 | 显示待处理/失败，保留恢复信息并允许重试 | P0-14 |

### 9.2 保存与删除语义

材料、课程设置和历史默认保留至用户删除。以下是前台访问与正式数据存储要求；备份清除周期见 V-08，上线前必须明确。

| 用户操作 | 必须清理或撤销 | 必须保留或解释 |
|---|---|---|
| 删除一份材料 | 原文件、解析内容、检索索引及非必要临时副本；撤销原文件访问。先取消依赖它的运行任务 | 历史题卷保留；其引用仅保留必要的来源标识并标“原材料已删除”，不继续提供被删原文。当前课程标记受影响项并要求复核 |
| 删除一份试卷 | 题卷、mark scheme、两个 PDF、该卷相关内容缓存及去重索引 | 课程材料和其他练习保留；不再用已删除卷的内容参与后续检索或去重 |
| 删除课程 | 取消课程相关任务；删除其材料、索引、草稿/确认版本、题卷、答案、输出文件和含内容的关联记录；撤销链接访问 | 其他课程保留。必要运行统计可去除内容和关联后保留，但不得借日志保留被删课程全文 |

删除涉及的副本和缓存必须纳入清理范围；不能只从页面列表隐藏。清理完成前显示真实状态，先阻止继续访问，不让删除中的资源仍可被新任务使用。恢复旧备份时必须继续遵守已确认删除记录，不能让删除内容重新对用户可见。

### 9.3 问题反馈的最小范围

首版提供“题目条件或范围问题、答案/评分问题、图表或排版问题、任务/下载问题、其他”分类和可选说明。反馈关联稳定任务/题目标识，不要求用户重复上传所有资料。反馈不会改变原结果，也不承诺在固定时间内完成专业批复。处理方的访问仅限诊断所需授权内容，不默认开放其他课程或其他用户数据。

## 10. 非功能要求与运行诊断

### 10.1 性能口径

| 指标 | 开始时间 | 结束时间 | 目标 |
|---|---|---|---|
| NFR-01 课程分析 | 所需材料上传完成且用户提交分析被受理，两者均满足时 | 首版可编辑课程分析及其范围/结构摘要可见 | 小于 120 秒 |
| NFR-02 完整生成 | 用户提交已确认配置的生成请求被受理时 | 完整题卷与答案网页、两个 PDF 均已准备好且可下载 | 小于 120 秒 |

- 计时包含系统排队、模型处理、自动重试、必要检查与 PDF 渲染；不以首次文字出现或仅完成题干作为结束。
- 不计用户编辑和等待用户补充信息的时间；同时记录实际墙钟耗时、系统活动耗时及暂停原因，避免用暂停掩盖处理耗时。
- 成功、失败、取消、需要补充信息和超时均保留原始记录。报告所有受理任务数及各结果分布；正常受理任务中的失败/超时不能从性能报告中删除。人为故障注入单独报告，不在测试后把慢样本临时改成“异常样本”。
- 展示每次原始耗时和小于 120 秒的达标分子/分母，分课程、模式、难度拆分。平均值或分位值可补充，不能替代两分钟目标。
- 按三门真实课程资料规模和最大样本考试规格验证；文件数、大小、页数、图表/公式数量、试卷长度、并发、运行环境、冷启动/缓存状态均在验收前记录并冻结。
- 若该输入与负载范围内未达到目标，则记录未达标并优化或正式修订需求，不能自行缩小范围、降低内容质量或省略 PDF 来宣称达标。
- 两分钟后的最大运行时长、自动重试和成本上限另行确定，不能将“小于 120 秒”混同为供应商调用的固定超时参数。

## 11. Gold set、测试与发布验收

### 11.1 评测对象与证据边界

Gold set 由**固定生成任务、可信参考材料、检查规则和评价准则**组成，不要求所有正确的新卷与某份标准题逐字相同。主要对象是新生成的题目与 mark scheme；解答现成练习只能辅助校准评估者，不能代替生成能力测试。

学生操作流程不运行一套需要人工批准的 Gold set；离线版本评测也不等同于 P0-09 的基础一致性处理。发布验收是产品版本级别的决定，不是每份练习的人工审批。

### 11.2 初始资料与测试矩阵

按用户已提供的信息，初始材料安排如下；实际文件、页码、版本及答案完整性仍需接收后核对。

| 课程 | 正式试卷及官方解答 | 其他练习 | 已知限制 |
|---|---:|---|---|
| Accounting | 2 套 | 有答案，覆盖大部分考试章节 | 小练习较考试简单；正式解答有过程但无详细分步分值 |
| Business Analytics | 2 套 | 有答案，覆盖大部分考试章节 | 同上 |
| Quantitative Maths | 1 套 | 有答案，覆盖大部分考试章节 | 同上，正式样本更少 |

Rubric 是否可获取尚未确定；缺失不阻止原型或开发，但评分分配不能因此被当作官方金标。测试需要覆盖实际课程的计算、解释和较长案例/论述任务。

| 课程 | 完整模拟卷任务 | 章节练习任务 | 固定任务数 | 每个版本正常输出数 |
|---|---|---|---:|---:|
| Accounting | Foundation、Exam-standard、Challenge | Foundation、Exam-standard、Challenge | 6 | 18 |
| BA | Foundation、Exam-standard、Challenge | Foundation、Exam-standard、Challenge | 6 | 18 |
| QM | Foundation、Exam-standard、Challenge | Foundation、Exam-standard、Challenge | 6 | 18 |

每个固定任务执行三次，共 54 个正常场景的计划运行位置，全部成功时得到 54 份输出。异常案例和评估者校准案例独立统计；不使用异常案例替代正常覆盖，也不从结果中删除未成功输出的尝试。失败仍占原计划运行位置；补跑时保留原始失败，单列补跑，不以补跑的成功覆盖原始结果。

### 11.3 Gold set 建立和维护步骤

1. **资料登记**：记录文件、课程、版本、来源类型、考试范围、官方解答和 rubric 可用性，定位重要公式/表格/图形。
2. **参考基线**：人工核对可确定的范围、知识要求、考试结构和来源证据，区分事实、推断、缺口及需要进一步核实的判断。
3. **任务冻结**：为 18 个任务建立稳定标识，保存材料版本、课程版本、模式、章节、难度、题型、题量和确认结构；三个重复使用同一任务定义。
4. **评估者校准**：使用有官方解答的题目和小练习核对评估能力，记录偏差。低难度练习上的正确性不能直接证明对正式考试复杂题的评价可靠。
5. **基线试跑**：生成并评估输出，识别评分表是否可执行，确定开放题、难度风格、重复率及可核验覆盖等阈值。
6. **冻结验收口径**：在正式验收输出前锁定阈值、评价提示、数值容差和样本处理规则；不能因看到正式结果不好而修改规则。
7. **版本验收及回归**：按冻结任务执行每个待验收版本的 54 次生成，另跑异常用例；修复后复测影响项，并保留旧报告。
8. **维护**：课程范围或任务变化时产生新的评测集版本，说明与之前不可直接比较的部分；不能把不同任务集的分数直接当迭代提升。

### 11.4 验证方法

| 方法 | 执行方式 | 能证明什么／不能证明什么 |
|---|---|---|
| 独立解答新题 | 评估 AI 先仅见新题及必要课程依据，不看生成的 mark scheme；提交独立解答后再比较 | 能发现不一致、条件不足及解题障碍；两个 AI 一致仍不是客观正确证明 |
| 数值与规则核验 | 对可计算部分复算、代入、检查恒等关系、单位、容差和分值汇总 | 对被检查项目提供客观证据；未覆盖项目不能记为通过 |
| 范围与来源核验 | 将题目要求映射到确认知识范围，检查引用是否实际支持结论 | 验证课程适配和出处；来源能打开不等于内容支持 |
| 重复生成比较 | 对三次输出及课程历史比较结构、解法、知识覆盖 | 验证重复倾向与覆盖变化；措辞不同不等于新题 |
| 异常及对抗材料 | 删除关键材料、制造冲突/不可读内容，插入要求改变规则的文档文字，注入任务失败 | 验证暂停、继续、拒绝与恢复是否正确；正常成功率不能替代异常正确处理 |

主要测试者为产品负责人和另一个 AI。老师、学过课程的学生只提供零星定性反馈；不将大规模专业人工标注作为首版的隐含前提。评估 AI 和生成过程应分开保存输出，避免先看到生成答案后再“独立求解”。

### 11.5 指标、分母与通过条件

所有比例同时保存分子、分母、未检查/无法判断数量和样本标识。分母为零时标记“不适用”，不记为 100%。结果按课程、模式、难度拆分；同一版本的重复输出也不能仅挑最好的一次报告。

| 指标 | 计算或记录方式 | 首版验收处理 |
|---|---|---|
| 配置符合率 | 符合确认题型、题量、分区、总分和选答的检查项数／适用检查项数 | 固定样本确定性要求 100% |
| 范围符合率 | 符合已确认范围的作答要求数／全部已核查作答要求数，附核查覆盖率 | 已验证的范围外要求必须修复；不能用未核查项补足通过率 |
| 题答与分值一致 | 对应完整且分值一致的题/结构项数／相关检查项数 | 确定性要求 100%；缺答案或错对应为严重问题 |
| 独立答案一致率 | 独立解答与生成答案相容的题数／可比较题数 | 单列辅助指标，不命名为准确率 |
| 客观检查覆盖率 | 已执行数值/规则核验的项数／可适用核验项数 | 与通过率同时报告；所需覆盖阈值在基线后冻结 |
| 客观检查通过率 | 正确通过的项数／已检查项数，注明容差依据 | 已确认的严重错误修复并复测；不能以整体平均分抵消 |
| 来源可定位与支持 | 可定位引用数／引用数；真实支持结论的引用数／已核查引用数 | 两项分别记录，不能只检查链接；外部补充说明需完整 |
| 开放题要点与事实 | 必要要点覆盖、事实错误、论证合理性、答案与评分一致性 | 有依据部分作为参考金标；质量量表和阈值在基线后冻结 |
| 难度与风格 | 按固定量表评价推理步骤、综合程度、计算量、解释要求及模板吻合 | 与官方样本/课程要求比较；未校准课程不能声明难度已匹配 |
| 实质重复率 | 与参考集合存在实质重复的新题数／已检查新题数，附检查覆盖率 | 上传题与历史分别统计，同一新题命中多次只计一次；阈值在基线后冻结 |
| 累计知识覆盖 | 多次输出中经核对已覆盖的知识点数／目标知识点数 | 使用冻结的知识树；记录未覆盖内容，不承诺固定套数全覆盖 |
| 异常正确处理率 | 正确识别并提供适当恢复的案例数／该类异常案例数 | 第 9.1 节各类用例需有通过证据 |
| 误阻断／漏阻断 | 被错误阻止的可继续样本数／可继续样本数；错误放行数／应暂停样本数 | 两项分开报告，覆盖局部解析失败和无历年卷情形 |
| 输出完整性与可读性 | 缺页、截断、错位、公式/图表损坏和答案泄漏的检查记录 | 完整预览及两个 PDF 均需检查；已确认的关键缺陷不能上线 |
| 运行与性能 | 全部受理任务结果分布；分析/生成各自小于 120 秒的任务数／对应全部受理任务数 | 依第 10.1 节记录；不能用平均值或删样本替代目标 |

**严重内容错误**至少包括：在题目约定下可确认的错误计算/结论；使目标题目无法合理作答的缺失条件；相互矛盾的条件；超出确认范围的必要知识；缺失或错误对应的答案；会导致错误自查的关键评分解释。合理的开放答案差异本身不算严重错误。

缺少官方 rubric 时，能够核实的事实、方法和必要观点作为参考；生成的建议评分不是金标。合理替代答案不因不同于官方示例措辞而直接判错。没有证据解决的争议标记“待核实”，不能计为已验证通过；这类样本的占比和可核验覆盖要求需在正式验收前冻结。

### 11.6 功能与异常验收场景

| TS-06 | 旧卷与当前范围不一致；两个当前声明彼此冲突 | 前者正确应用当前范围；后者要求澄清，保留双方证据 | P0-05、P0-06 |
| TS-07 | 编辑课程后新增/替换/删除材料，再打开草稿和旧卷 | 人工修改保留、差异可见、需重新确认；历史快照不变 | P0-06、P0-11 |
| TS-08 | 两种模式、三档难度，修改章节、题型及大题数 | 控制项真实生效；新结构展示差异且先确认 | P0-07、P0-08 |
| TS-09 | 多知识点大题、含多个小题、选答分区、分值不一致的结构 | 有效综合题结构不误拒绝；无效分值或选答不能提交 | P0-07、P0-09 |
| TS-10 | 计算、解释和案例/论述题，含课程需要的图表 | 新题条件可用，答案完整，评分性质明确，图表必要信息保留 | P0-08、P0-10 |
| TS-11 | 注入缺答案、错题号、错分值、超纲和仅换数字的重复题 | 内部检查识别并修复或明确失败，不假称成功 | P0-09 |
| TS-12 | 查看长卷与答案，分别下载、打印，模拟一个 PDF 失败 | 两份独立文件同版本；重导出沿用原内容；未齐备不完成 | P0-10 |
| TS-13 | 刷新、退出登录、重启会话，打开历史及再次生成 | 状态持久恢复；原卷不变；再次生成独立记录且核对当前版本 | P0-11、P0-12 |
| TS-14 | 双击提交、双标签提交、断网重连、超时、取消与晚到结果 | 不重复出卷；正确恢复；超时继续但记不达标；取消后不复活 | P0-12 |
| TS-15 | 目标章节证据不足；联网补充成功、失败和冲突；无关章节缺资料 | 补充来源明确；仍不足则暂停；可完成章节不误阻断 | P0-04、P0-13 |
| TS-16 | 分别删除材料、试卷和运行中课程；尝试访问旧链接 | 原文/索引/输出按规则清理，引用标失效，任务和权限联动 | P0-14 |
| TS-17 | 提交题目错误反馈，模拟提交失败并重试；检查诊断记录 | 可定位问题、说明不丢失、无无意义重复；日志无密钥或默认全文 | P0-14 |
| TS-18 | 文档内插入要求改变系统规则或访问其他课程的文字 | 作为材料数据处理，不改变访问权限或执行任意指令 | P0-03、P0-13；NFR-08 至 NFR-12 |
| TS-19 | 真实材料规模和冻结并发下运行分析及完整生成 | 记录真实阶段、所有尝试和两个端点耗时，不将示例计时作为证据 | NFR-01 至 NFR-05 |
| TS-20 | 从交付说明启动本地产品、使用受邀线上入口，检查键盘与窄屏及 PDF | 能独立完成完整流程；浏览器和阅读器支持范围明确 | P0-01 至 P0-14；NFR-06、NFR-07 |

### 11.7 发布判定

首版交付必须满足以下条件；报告标注通过、未通过或不适用及证据，不以文档已写完代替产品验收。

| 发布条件 | 必需证据 |
|---|---|
| P0 功能全部完成 | AC 验收记录及 TS 场景映射，真实材料到真实网页和两个 PDF 的端到端结果 |
| 内容评测完成 | 18 个任务、每任务三次的完整尝试记录，指标分子分母，异常报告与版本信息 |
| 严重已确认错误已解决 | 修复及复测证据；没有未解决的严重内容或关键输出错误 |
| 质量口径已冻结 | 开放题、难度/风格、重复、可核验覆盖等阈值在正式验收前确定；符合冻结标准 |
| 性能符合目标 | 输入与负载范围已冻结，分析/完整生成实测达标；失败和超时仍保留在报告中 |

正式评测尚未执行时，只能说明“验收方案已准备”，不能声称满足这些发布条件。若目标未达，应保留未通过结论；任何范围或目标修订需明确记录，不能由实现过程暗中改变。

## 12. 交付、启动、依赖、风险与待决事项

### 12.2 如何启动与使用

**现有原型**：用浏览器打开 `prototype/index.html` 即可审阅流程，无需 API 或后端。它只演示示例数据；不能作为本节正式产品启动的替代。

**现有代理准备**：按 [LiteLLM 本地接入说明](../LITELLM_SETUP.md)检查相关准备情况。该说明记录的模拟接口验证只证明准备工作，不证明真实模型、课程处理或出卷链路可用；本 PRD 不读取或记录任何密钥值。

**正式产品交付时必须提供的启动说明**：

1. 依赖和支持环境，包括数据存储、文件/PDF 处理、模型和任务执行所需组件。
2. 不含真实凭据的配置示例，哪些配置必需、在哪里配置，以及服务缺失时如何诊断。
3. 可复现的安装、初始化、启动、停止命令；实际本地访问地址和测试身份获取方式。
4. 真实材料导入、课程确认、第一次出卷、查看两个 PDF 的操作路径。
5. 受邀线上访问地址、受邀访问/恢复方式、运行限制和问题反馈方式。
6. 数据保存与删除说明，日志定位方法，以及取消、重试和任务恢复的验证方法。

目前正式产品尚未交付，不能提供假定可用的正式启动命令或线上地址。技术方案冻结后应将上述内容写成实测通过的运行说明，并关联本 PRD 的验收记录。
